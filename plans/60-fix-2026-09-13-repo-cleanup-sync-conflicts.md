# تنظيف المستودع من ملفات sync-conflict والوصول لنسخة عمل نظيفة (تمهيد لخطة 59)
> الإصدار: 1.0.0
> التاريخ: 2026-09-13
> الحالة: مسودة — بانتظار اعتماد المطور

## الهدف

المستودع فيه 100 إدخال غير نظيف في `git status` — أغلبها (68 ملف) نسخ `sync-conflict` مكررة من Syncthing، والباقي (32 إدخال) خليط من تعديلات حقيقية غير مثبتة، مستندات، وملفات سكرِبت مؤقتة. الهدف من الخطة دي:

1. حسم مصير كل ملف من الـ100 بأمان — نحتفظ بأي شغل حقيقي، ونشيل التكرار والقمامة، من غير ما نفقد حاجة.
2. الوصول لنسخة عمل (`working tree`) مطابقة تماماً لآخر commit معتمد ومتزامنة مع GitHub، عشان تبقى نقطة انطلاق نظيفة لخطة 59.
3. حسم فرع النشر (`master` مقابل `main`) بمعرفة المطور، لأن خطة 59 بتفترض "نسخة نظيفة" و"فرع نشر محسوم" كشرطين مسبقين.

## الوضع الحالي (نتائج الفحص — أرقام حقيقية من المستودع)

### 1. الفروع والـ remote

| الفرع | آخر commit | الحالة |
|-------|-----------|--------|
| `master` (محلي، الحالي) | `a3dbf00` | **مطابق تماماً** لـ `origin/main` و `origin/master` (نفس الـ SHA بالضبط) |
| `origin/main` | `a3dbf00` | يشير إليه `origin/HEAD` — هو فرع النشر الفعلي على Cloudflare Pages |
| `origin/master` | `a3dbf00` | مطابق لـ `origin/main` تماماً |
| `origin/prelaunch-2026-05-06` (الفرع اللي `master` المحلي "بيتابعه" حسب `git branch -vv`) | `b162eea` | **متأخر** — ناقصه commit-ين (`087a62a`, `a3dbf00`) شاملين خطة 54 وخطة 57 |

**الخلاصة المهمة:** المحتوى فعلاً محدّث — `master` المحلي مطابق حرفياً لـ `origin/main` (نفس الـ commit hash، `git diff` فاضي تماماً بينهم). المشكلة مش إننا محتاجين نسحب كود جديد من GitHub، المشكلة إن الفرع المحلي بيتابع (`tracking`) فرع `prelaunch-2026-05-06` القديم بدل `main`، وده بيخلي `git status`/`git push` الافتراضي يحسب المسافة غلط ("ahead by 2"). **الفحص ده تم بفحص الـ refs المحلية المخزنة عندي فقط — لسه محتاج `git fetch` (خطوة أولى في التنفيذ) للتأكد مفيش commits جديدة اتدفعت على GitHub من وقت آخر مزامنة محلية.**

### 2. ملفات sync-conflict (68 ملف)

- **كلها untracked** (`??` في `git status`) — مفيش ولا واحدة منها اتحفظت في تاريخ git من قبل.
- بتتوزع على **34 ملف أصلي**، كل واحد منهم له **نسختين** conflict (تاريخ `20260519` و`20260520`).
- **تحقّقت:** كل زوج (النسخة بتاريخ 19 والنسخة بتاريخ 20 لنفس الملف) **متطابق بايت-لبايت** (`diff -q` رجع فاضي) — يعني الـ68 ملف فعلياً هم 34 محتوى فريد مكرر مرتين، مش 68 نسخة مختلفة.
- **تحقّقت من المحتوى:** كل نسخ الـconflict بتاريخ تعديل (`mtime`) = 6 مايو 2026، يعني هي لقطة قديمة من وقت "pre-launch website updates" (commit `b162eea`)، **قبل** كل التعديلات اللي اتعملت بعد كده والمعتمدة فعلاً في `HEAD` الحالي (خطة 54 يوم 18 مايو، خطة 57 يوم 10 يوليو، تحديثات project-context لحد 23 يوليو).
- **عيّنة مقارنات فعلية:**
  - `index.html` الحالي (working tree) **مطابق 100% لـ `HEAD`** (`git diff --stat HEAD -- index.html` فاضي) — يعني الملف الحالي مش فيه أي تعديل غير محفوظ. مقابل نسخة الـconflict: فرق **2016 سطر** عن `HEAD` (نسخة قديمة قبل خطة 54 و57).
  - `changelog.md`: النسخة الحالية 17,498 بايت (آخر تعديل 10 يوليو) مقابل نسخة الـconflict 12,740 بايت (6 مايو) — فرق حجم كبير يعكس إضافات لاحقة موثقة أصلاً في الملف الحالي.
  - `project-context.md`: نسخة الـconflict (6 مايو، 11,933 بايت) بتوقف عند "الموقع لسه في pre-launch"، بينما النسخة الحالية (29,896 بايت) موثق فيها كل حالة خطة 54، 55، 57، 58 وتحديثات لحد 23 يوليو. مفيش أي معلومة في نسخة الـconflict مش موجودة (بصيغة أحدث) في النسخة الحالية.
  - نفس النمط تكرر في `project-key.md` و`sitemap.xml` وكل صفحات `services/` و`en/services/`.
- **الخلاصة:** الـ68 ملف كلها نسخ قديمة تجاوزتها التعديلات المعتمدة فعلاً، ومفيش فيها أي محتوى فريد غير موجود في النسخة الحالية أو في تاريخ git. **آمن حذفها بعد نسخة احتياطية** (خطوة إلزامية أدناه، مش افتراض بدون تحقق).

### 4. `.gitignore`

المحتوى الحالي:
```
# Local secrets - never commit (Plan 58 OAuth credentials, refresh tokens)

```

**لا يستثني** أنماط `*.sync-conflict-*` ولا `docs/cloudflare_Token.md` ولا `.claude/settings.local.json` ولا `scratch/`/`temp_archive/`. ده سبب مباشر ليه ملفات الـsync-conflict ظهرت في `git status` كـ untracked بدل ما تتجاهل من الأساس — Syncthing هيستمر يعمل نسخ conflict مستقبلاً طالما الأداتين (git + Syncthing) شغالين على نفس المجلد بدون استثناء.

## المتطلبات

- عدم فقدان أي شغل حقيقي (خطط، مستندات، تعديلات project-context/project-key/plan-54).
- نسخة احتياطية موثقة (فرع git أو أرشيف خارج المستودع) **قبل** أي حذف جماعي.
- كل أمر حذف جماعي (`git clean` أو ما شابه) يُعرض بـ `--dry-run` على المطور قبل التنفيذ الفعلي.
- تأمين `docs/cloudflare_Token.md` فوراً كأولوية أمنية، منفصلة عن باقي التنظيف.
- تحديث `.gitignore` ليمنع تكرار مشكلة sync-conflict مستقبلاً.
- حسم المطور صراحة لفرع النشر ولحساب GitHub قبل أي `fetch`/`pull`/`push`.
- الوصول النهائي: `git status` نظيف (لا شيء غير مفسَّر)، و`working tree` مطابق لـ `origin/main` زائد أي commits جديدة موثقة بوضوح.

| تسرّب Cloudflare API Token في commit مستقبلي | نقله فوراً في المجموعة 1 قبل أي `git add`، ويُنصح بتدوير الـ Token لاحقاً كإجراء احترازي |
| الخلط بين "تحديث من GitHub" و"الفرع أصلاً محدّث" يؤدي لعمل `pull`/`merge` غير ضروري وربما يكسر شيئاً | التقرير يوضح صراحة إن `master` = `origin/main` بالفعل (نفس commit) — لا حاجة لـ merge، فقط تصحيح مرجع التتبع |
| حذف فرع remote قديم يفقد تاريخاً مفيداً لاحقاً | حذف الفروع البعيدة **غير مُدرج ضمن التنفيذ التلقائي** لهذه الخطة — بند قرار منفصل فقط |
| فقدان سكربتات `scratch/`/`temp_archive/` قد تكون مرجعية لعمل مستقبلي مشابه | لا حذف تلقائي — بند قرار صريح للمطور، مع اقتراح أرشفة خارج المستودع بدل الحذف النهائي |

## مسار الرجوع (Rollback)

1. الفرع الاحتياطي `backup/pre-cleanup-2026-09-13` (من المجموعة 1) يحتفظ بكامل حالة المستودع (متتبَّع وغير متتبَّع عبر commit/stash) قبل أي حذف — أي ملف اتشال يمكن استرجاعه منه بـ `git checkout backup/pre-cleanup-2026-09-13 -- <path>`.
2. النسخة الخارجية (خارج مجلد المستودع، من المجموعة 1) تغطي نفس الملفات كطبقة أمان مستقلة عن git، للرجوع لو الفرع الاحتياطي نفسه اتأثر بطريق الخطأ.
3. لو أي خطوة في المجموعة 4 (تعديل مرجع التتبع) سببت التباس، الحل فوري وآمن: `git branch --set-upstream-to=origin/prelaunch-2026-05-06 master` يرجّع الوضع القديم — العملية مجرد مرجع، لا تلمس أي كود أو commit.
4. لا يوجد أي `push` أو حذف فرع remote في هذه الخطة، فمفيش خطوة هنا غير قابلة للرجوع على مستوى GitHub نفسه.
