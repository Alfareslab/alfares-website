# خطة 58 — مزامنة تقييمات جوجل الحقيقية (Business Profile API + أتمتة أسبوعية)
> الإصدار: 3.0.0 — تحوّل من Places API إلى Business Profile API (تحل محل v2.0.0)
> التاريخ: 2026-07-15
> الحالة: مسودة نهائية — بانتظار الموافقة قبل أي تنفيذ
> **المراجع البحثية:** `docs/reviews/58-01-google-reviews-research-perplexity.md`, `docs/reviews/58-02-google-reviews-research-gemini.md`
> **سبب التحول من v2.0.0:** Places API يتطلب ربط بطاقة/فوترة على مشروع Google Cloud (شرط ثابت من جوجل لكل خدمات Maps Platform، حتى لو التكلفة الفعلية شبه معدومة). المطور فضّل تجنّب ربط أي بطاقة نهائياً. **Business Profile API مجاني بالكامل ولا يتطلب فوترة خالص** — البديل: تسجيل دخول OAuth لمرة واحدة بدل البطاقة، مع فايدة إضافية: وصول لكل الـ 100 تقييم بدل 5 بس.

## السياق

قسم "آراء العملاء" في `index.html` و`en/index.html` بيعرض حالياً:
- **21 تقييم مكتوبين يدوياً وثابتين** في `assets/js/reviews.js` (array مدموج جوه الملف)، آخر تاريخ فيهم **15 يناير 2025**.
- رقم **"4.8"** كمتوسط تقييم — **نص ثابت** في الـ HTML (`index.html` سطر ~745)، مش مرتبط بأي بيانات حقيقية رغم وجود دالة `calculateAggregateRating()` غير مستخدمة فعلياً في تحديث الـ DOM.
- زرار "أضف تقييمك" (`index.html` سطر ~755) — رابط حقيقي لكتابة تقييم جديد على Google (`https://search.google.com/local/writereview?placeid=ChIJUcxYm4vPwxURdM5oL0ZZK7M`).

**التقييم الحقيقي الفعلي على Google Business Profile الآن: 4.8 من 100 تقييم.**

## الهدف

استبدال قسم التقييمات الثابت بنظام يعكس الواقع الحقيقي على Google تلقائياً وبشكل دوري، **بدون ربط أي بطاقة/فوترة**، وبدون build step جديد، ومن غير ما نأثر على سرعة أو أمان الموقع.

## المتطلبات

- عدم كشف أي من أسرار OAuth (Client ID/Secret/Refresh Token) للزوار — تُخزَّن فقط كـ GitHub Secrets.
- عدم التأثير على سرعة تحميل الصفحة — لا استدعاء شبكي لجوجل وقت زيارة أي مستخدم.
- الحفاظ على فلسفة "لا build step" — التعديل الوحيد على آلية العرض هو تغيير مصدر البيانات في JS الموجود.
- عدم حذف أو فقدان الـ 21 تقييم القديمة نهائياً من الأرشيف — يُقترح نقلها لملف أرشيفي منفصل غير معروض بدل حذفها (قرار نهائي يُتّخذ في المجموعة 4).
